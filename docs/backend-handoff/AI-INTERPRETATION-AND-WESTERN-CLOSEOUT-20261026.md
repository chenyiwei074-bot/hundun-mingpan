# 混沌全站 AI 解读与西方功能收口交接

日期：2026-10-26  
用途：交给后端逐项回复/实现；不授权修改八字、紫微或六爻既有排盘算法。

## 一、产品裁定

1. 用户先选一个工具；该次 AI 只读取这个工具已经算出的结果，不调用、不引用、不比较其他术数。六爻解读只用六爻数据，梅花只用梅花数据，以此类推。
2. 盘面/牌面/数值由对应确定性规则计算，是事实基准。AI 只能解释和组织这些事实，不能重排、改数、补算或把推断写成盘面事实。
3. 不要求不同工具对同一现实问题给出相同的术数判断，也不把不同体系结果并排合成为结论。若用户在当前工具中要求另一体系，明确说明本工具范围，不跨体系作答。
4. 面向用户的称呼统一为“混沌自研 AI”。接口、页面、错误、保存记录和隐私文案不得出现其他模型/供应商名称，不得提供模型选择入口。
5. AI 不得自报或生成 `sourceId`。只有服务端来源登记表中已核验的来源才能显示；无匹配时标“本站自研”。

## 二、当前实现盘点

- `POST /api/ai/interpret` 与 `ToolInterpretation` 已为梅花、六爻、星宿、黄历、姓名五格、数字命理、月相、跨盘相位、本命行星、大运、户型九宫提供独立 profile。
- 东方合盘已有后端 `hepan` profile，但当前前端合盘页没有挂 AI 解读卡，需要前端补入口并采用最小化盘面 payload。
- 塔罗已有独立 `POST /api/tarot/reading`，支持单牌、三张、五张、凯尔特十字和正逆位；页面保留逐牌与综合解读及 7 天保存。该路径不要重复新建通用塔罗接口，但响应里不应对用户暴露内部 `model` 字段。
- 八字/紫微命盘沿用现有命盘分析管线；姓名不进入 AI 请求。不得把 `chartData`、原始出生资料或 visitor 标识整体透传。
- 前端调用点已逐项改为发送最小化、已计算的结果字段；后端仍需按 `tool` 建立字段白名单，不能信任客户端 allowlist，也不能把原始整份 API 响应当作 prompt 输入。
- 韦特—史密斯 78 张牌义的来源核验已完成（PASS 78/78），后端来源登记已有 `tarot-<cardId>`。校对记录见 `docs/source-review/README-tarot-verification.md` 与 `docs/source-review/`；无需重复登记或重做这一批。
- 前端已把西方本命宫制开放范围扩为七种；整宫、等宫、三分、Placidus、Koch 有现存 20 组对拍夹具。Regiomontanus/Campanus 已接入实现，但尚缺独立参考夹具，因此本次请后端补充对拍资料并复核，不得把前四种夹具说成覆盖全部七种。
- 前端已在东方合盘结果中接入 `hepan` 解读入口；其它已接入页面也只向解读组件传已计算结果的最小字段。后端需用按工具白名单和事实引用校验落实同一边界。

## 三、请求与结果契约

### 请求

维持同域 `POST /api/ai/interpret`，不新增模型选择参数：

```json
{
  "tool": "liuyao",
  "question": "用户可选填写的问题，最长 300 字",
  "payload": {
    "result": "该工具的白名单计算结果"
  }
}
```

服务端按 `tool` 选择固定 profile/schema；拒绝未知字段或超限数据。不要把原始整份 API 响应当作 prompt 输入。问题文本是用户输入，按现行隐私披露随本次请求处理；日志不得记录原始问题、完整 payload 或拼好的 prompt。

### 返回

通用解读响应应保持可机器校验的结构：`mode`、`aiReady`、`title`、`summary`、`sections[{id,title,body,factRefs,sourceIds}]`、`notes`。`factRefs` 只能指向本次白名单结果内的字段路径/事实编号；服务端校验引用存在后才返回。`sourceIds` 必须由服务端登记表覆盖生成，不能信任模型输出；前端按章节展示已核验来源，没有可核验来源时显示“本站自研”。不可判断时必须能返回明确的“不足以判断”，不可用套话补齐结论。

塔罗继续返回牌位与逐牌解读，另有综合摘要；保持输入牌序、牌位、方向不变。公开响应移除 `model` 等内部实现字段，只保留 `mode/aiReady` 与“混沌自研 AI”口径。

各 profile 必须有服务端字段白名单，不接受前端传来的 `systemPrompt`、`sourceIds`、provider/model 名称或任意指令字段。对客户端输入一律当作数据，不当作系统指令。

## 五、解读一致性与安全验收

1. 先由服务端生成“事实账本”：每个允许解释的事实有稳定 ID/字段路径；输出各段必须引用账本中的 `factRefs`。事实与推断分区展示。
2. AI 无权改写事实账本。若输出与账本数值、方向、牌位或规则结果矛盾，丢弃 AI 输出并走明确标注的规则回退；不要静默修正盘面。
3. 每个请求只能属于一个 `tool`。任何提示注入或用户要求跨体系的问题都不能改变 profile，也不能把别的工具数据补进来。
4. 不可由当前工具字段支持的天气、医疗、投资、法律或确定性人生结论，明确说明此结果无法判断；不能输出“明天一定下雨”这类客观事实预测。
5. 引用只由服务端依据登记表附加；AI 原始 JSON 中即使包含 `sourceIds`/书名/页码也全部丢弃。韦特—史密斯 78 张已有已核验来源登记；没有对应登记的六爻、紫微、风水、合盘、马赛牌义等章节继续显示“本站自研”，不补造来源。
6. 全不可用/输出不合格时，标明“混沌自研 AI 解读暂不可用；以下仅为规则结果”，不可把规则摘要伪称 AI 生成。
7. 后端回复应附接口契约、各工具字段白名单、错误码、隐私日志检查结果及单测覆盖表；不得更改前端之外的算法结果。

## 六、最后两项西方功能收口

### A. 本命占星宫制

当前前端实现并开放：整宫、等宫、三分（Porphyry）、普拉西德、科赫、雷吉奥蒙塔努斯（Regiomontanus）、坎帕纳斯（Campanus）七种宫制；选择器会按当前出生时刻和地点重新计算。极区/退化盘明确提示不适用，不用近似值伪装。产品范围收口为这七种。

- 已有对拍：20 组输入覆盖 Equal、Porphyry、Placidus、Koch，与 Swiss Ephemeris/Celestine 参考值比较，公差 0.05°。
- 前端待补独立验证：Regiomontanus 与 Campanus 已有公式实现，但现有夹具没有这两制的预期值。请后端提供 20 组输入及两种宫制的参考宫头（注明参考实现、版本、纬度与极区规则），或给出可复现的权威算法来源；不要将已有四种宫制夹具误称为七种全覆盖。
- 请复核七种在有效纬度下均返回 12 个有限宫头，并确认 Asc/MC 与角度引擎一致；极区样本应显式返回“不适用”。不得修改用户现有出生时刻换算和行星排盘算法。

### B. 塔罗跨牌系比较

当前前端开放范围为：四种牌阵、韦特—史密斯 78 张正逆位牌义、牌面和抽牌可复核、7 天保存，以及与马赛牌系的牌名/编号/图像结构对读。韦特来源已核验并登记 78 张；马赛逐张传统牌义尚未核验。

- 请提供可核验的马赛牌义来源登记材料（版本、作者/编者、出版信息、卷/页、原文或可靠译本位置、公版/授权状态）；逐张标明实际覆盖牌与正逆位依据。不能把韦特牌义直接移植到马赛牌。
- 前端目前只展示“结构对读”与范围说明；取得校核通过的马赛材料及 sourceId 后，再扩展到马赛正逆位牌义对读。未交付前不得声称马赛牌义完整，也不得伪造 sourceId。
- AI 只整理已核验并登记的牌义，不从牌图自行生成所谓“传统牌义”。
