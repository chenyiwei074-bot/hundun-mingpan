# 已知四柱独立解读：后端交接

日期：2026-10-26  
基线：`06f3d206`  
用途：为前端 `/create` 的“已知四柱”模式提供纯计算接口与独立 AI 解读 profile。

## 产品边界

- 用户输入年、月、日、时四柱；本功能只分析输入的八字结构。
- 不从四柱反推出生日期、时刻、地点或真太阳时；不生成紫微、大运、流年或起运结果。
- 不调用完整命盘创建流水线，不写入 `charts`、`reports`、用量记录或分享数据。
- 不要求姓名、性别、出生地、现居地、visitorId；计算接口请求不得含这些字段。
- 不改现有八字、紫微或六爻算法；复用已有 `enrichBazi(siZhu)`。
- AI profile 对外只称“混沌自研 AI”；不返回 provider/model，不接受模型选择字段。

## 1. 四柱计算接口

### 路由

`POST /api/bazi/pillars/calculate`

注册至现有 Express `/api` router。该接口是同步、无持久化的计算接口。

### 请求

```json
{
  "siZhu": {
    "年": { "gan": "甲", "zhi": "子" },
    "月": { "gan": "丙", "zhi": "寅" },
    "日": { "gan": "戊", "zhi": "辰" },
    "时": { "gan": "壬", "zhi": "子" }
  }
}
```

仅接受 `siZhu` 根字段，且只接受“年、月、日、时”四个柱位；每柱只接受 `gan`、`zhi`。拒绝未知键、数组、空值、非字符串及缺失柱位。

### 校验

- 天干必须为 `甲乙丙丁戊己庚辛壬癸` 之一；地支必须为 `子丑寅卯辰巳午未申酉戌亥` 之一。
- 每柱必须是六十甲子中的合法配对：天干与地支序号同奇偶。
- 只校验单柱合法配对，不推测出生时间，也不静默调整四柱之间的关系。
- 不接受 `calendar: "四柱"` 传入 `/chart/create`；此功能走独立路由。

### 计算与响应

- 调用现有 `enrichBazi(siZhu)`，不复制或修改其中规则。
- 返回用户输入的四柱原值与 `enrichBazi` 结果：

```json
{
  "success": true,
  "data": {
    "siZhu": {
      "年": { "gan": "甲", "zhi": "子" },
      "月": { "gan": "丙", "zhi": "寅" },
      "日": { "gan": "戊", "zhi": "辰" },
      "时": { "gan": "壬", "zhi": "子" }
    },
    "enrichment": {}
  }
}
```

`enrichment` 使用现有类型/结构，包含五行统计、旺衰、格局、调候、天干关系、地支关系、整柱与自坐等已有字段；不得补入生日推算、紫微或大运字段。

### 错误

- `400 invalid_pillars`：字段缺失、未知字段或类型错误；错误消息说明具体柱位。
- `400 invalid_ganzhi`：某柱不是合法六十甲子配对；错误消息指明年/月/日/时柱。
- `500 calculation_unavailable`：规则计算失败；返回通用中文错误，不回显堆栈或原始请求。

## 2. AI 解读 profile

前端复用 `POST /api/ai/interpret`，新增工具名 `bazi-pillars`。请求形态：

```json
{
  "tool": "bazi-pillars",
  "question": "",
  "payload": {
    "siZhu": { "年": {}, "月": {}, "日": {}, "时": {} },
    "enrichment": {}
  }
}
```

要求：

- 白名单仅接受 `siZhu` 与 `enrichment`；拒绝 visitorId、姓名、出生信息、provider/model、systemPrompt、sourceIds 和额外术数结果。
- Profile 只解释四柱和 `enrichBazi` 已计算字段，不重算盘面，不调用紫微、大运或其他术数。
- 每个 section 的 `factRefs` 必须指向本次请求真实存在的四柱/增强字段；未知引用丢弃或让本次 AI 结果回退。
- `sourceIds` 由服务端登记逻辑覆盖。没有已核验古籍匹配时一律 `[]`，前端显示“本站自研”。
- AI 不可用时仍保留计算接口返回的规则结果，前端明确显示 AI 解读暂不可用。
- 对外响应不暴露 provider/model，不写入原始 payload、拼接 prompt 或四柱值日志。

## 前端现状

- `/create` 的单人历法切换增加“已知四柱”，双人合盘仍只支持公历/农历。
- 前端只调用 `/api/bazi/pillars/calculate` 传 `{ siZhu }`；结果在当前页面展示，不进入命盘加载、保存或分享流程。
- AI 卡只在用户点击时发送 `siZhu + enrichment` 至通用 AI 解读接口。
- 后端未实现两个契约前，前端构建可通过，但“已知四柱”计算请求会显示接口不可用；不得据此宣称线上功能已完成。

## 后端验收

- 合法请求 200 且四柱原值不变，增强字段等于现有 `enrichBazi` 对同一输入的输出。
- 非法干支、缺失柱位和未知字段按 400 返回；不得错误进入 `/chart/create`。
- 计算请求和 AI 请求不创建数据库记录；检查日志不包含原始四柱或完整 prompt。
- `bazi-pillars` 未知字段拒绝；事实引用路径真实存在；模型自报 sourceIds 不会透传。
- 不修改既有完整命盘的八字、紫微、大运、起运或六爻计算。
