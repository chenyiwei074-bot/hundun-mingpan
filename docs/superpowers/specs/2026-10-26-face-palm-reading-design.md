# 面相与手相照片解读设计

日期：2026-10-26  
状态：待用户审阅  
范围：在现有混沌站点增加东方面相、手相的照片识别与辅助解读；不改八字、紫微、六爻算法。

## 产品目标

用户分别进入面相或手相工具，提交一张本人选择的照片，经明确同意后识别可见特征。用户检查并确认识别结果，再请求混沌自研 AI 按本站对应传统文化口径解释这些特征。识别与解读分两步，AI 不直接看图，也不替用户确认识别事实。

两个工具使用独立页面与独立 AI profile，放在东方工具目录。复用上传、预览、确认、错误和结果呈现组件；不合并成一个混合解读。

## 页面流程

1. 页面说明图片用途、本站不保存原图及文化参考范围；用户确认图片为本人，或已取得被拍摄者明确同意，并勾选同意后才允许选择和提交图片。
2. 仅接受 JPEG、PNG、WebP，单张不超过 5 MB。面相要求一张正面、无遮挡的人脸图；手相要求一张掌心朝向镜头、主要掌纹可见的手掌图，并由用户选择左手或右手。
3. 页面显示本地预览与移除/重选操作。用户主动开始识别后才上传图像；开始前不预取、不预上传。
4. 识别接口只返回可见结构特征候选、位置标记和置信度。无法识别或置信度不足时明确显示原因，不补造结果。
5. 用户逐项确认或修正候选。只有至少一项有效确认后才开放 AI 解读；AI 请求只携带用户确认的结构化特征，不携带照片、姓名、生日、地点或 visitorId。
6. 用户可随时清除图像与当前结果。刷新页面后不恢复照片或解读状态；本版不保存记录，不写入“我的报告”。

## 识别边界

### 面相

- 只提取图像上可见的面部几何/外观描述，例如轮廓、眉眼、鼻、口、下颌等区域的可见形态与图像清晰度。
- 不进行身份识别、身份比对、年龄/性别/族裔推断、情绪判定或健康判断。
- 遮挡、滤镜、角度偏斜、出现多张脸或图像质量不足时返回可修复提示或 `unrecognizable`，不强行给出特征。

### 手相

- 只提取掌面轮廓与主要掌纹的可见走向、连续性和清晰度；掌线名称仅作为用户可校正的候选标签。
- 不进行身份识别、指纹识别、健康判断或医疗建议。
- 手掌反光、遮挡、出现多只手、焦点不足或无法区分掌纹时返回不确定状态。

以上是图像识别范围，不代表传统解释具有科学预测能力。解读只作为传统文化参考，不输出诊断、确定性寿命/婚姻/财富结论或对他人的评判。

## 前后端契约

### 图片识别

新增 `POST /api/physiognomy/recognize`。

请求仅接受：

```json
{"kind":"face","consent":true,"imageBase64":"data:image/jpeg;base64,..."}
{"kind":"palm","consent":true,"hand":"left","imageBase64":"data:image/jpeg;base64,..."}
```

`hand` 只用于 `kind=palm`。服务端检查 consent、MIME 与文件头一致性、大小和图像解码；拒绝未知字段。原图只在请求内存中短暂处理，不写磁盘、数据库、对象存储、缓存、报告或备份。响应和日志不得含图像正文、内部 provider/model 名称、提示词或原始图像 URL。

成功响应：

```json
{
  "ok": true,
  "kind": "face",
  "features": [
    { "id": "face-outline", "label": "面部轮廓", "candidate": "...", "confidence": 0.86, "region": [0.1, 0.1, 0.8, 0.8] }
  ],
  "notes": []
}
```

`region` 为可选的 0–1 归一化框；`confidence` 在 0–1，仅作模型给出的人工复核提示，不是统计概率或准确率承诺。即使置信度较高，所有特征仍须用户确认。无法识别使用结构化错误码，不返回猜测特征。公开响应保持通用，不暴露内部视觉服务配置。

建议错误码：`consent_required`、`bad_type`、`too_large`、`unrecognizable`、`low_confidence`、`timeout`、`vision_unavailable`、`invalid_request`。

### AI 解读

扩展 `POST /api/ai/interpret`，增加独立工具 `face-reading` 与 `palm-reading`。各自只接受对应 `confirmedFeatures` 与必要的界面选项；拒绝图片、原始出生资料、身份字段、客户端提示词和客户端 `sourceIds`。AI 不得把候选当成确认事实，不得跨体系混断。没有逐项核验底本时，章节来源显示“本站自研”，不伪造古籍出处。

### 日志与隐私

- 图片仅在用户同意并主动提交后上传；请求不写入访问日志或错误日志正文。
- 服务端临时 Buffer 在请求结束后释放；接口响应使用 `Cache-Control: no-store`，不返回可再次访问的图片 URL。
- 隐私页说明图像用途、用户确认步骤、本站不持久化原图、无报告保存，以及识别服务的处理限制。不得暗示处理过程中未调用服务端视觉识别服务；用户界面统一称“混沌自研 AI”，不显示内部服务名称。
- 上线前必须核对服务端视觉服务关于图片留存/训练的实际配置；若无法确认，不得在隐私页承诺服务链路各环节都不留存。

## 架构

- 前端：新增两个工具页、目录条目和共享 `PhysiognomyFlow`；识别候选确认后复用 `ToolInterpretation` 发送结构化特征。
- 服务端：新增独立 controller 与 recognition service；不复用户型图持久化 controller。提示词、schema 与输出验证按 face/palm 分开。
- 不新增数据库表，不保存原图、特征或解读；刷新即结束本次会话。
- 不登记未核验来源，不改 `classics-registry`。

## 验收

- 未勾选同意时不能选图、不能发网络请求；明确同意后才可上传。
- 前端与服务端都拒绝超限文件、错误 MIME/文件头和未知字段。
- 原图在站点磁盘、数据库、对象存储、报告与请求日志中均无持久副本；用户移除后立即清除浏览器预览与内存状态。
- 无人脸/无手掌、遮挡、低置信度、超时和服务不可用均有可操作的状态提示。
- AI 只在用户确认候选后请求，payload 不含图片或原始个人资料；成功与失败响应不暴露内部 provider/model。
- 桌面与 375px 手机视口可完成全流程，键盘可操作，尊重减少动态效果偏好。
- build、前后端契约检查、图片隐私检查和浏览器流程验收通过后再交付部署。

## 尚待产品实现时检查

1. 当前户型识别服务把图像写入磁盘并保留 7 天；面相/手相必须使用新内存链路，不能调用该持久化 endpoint。
2. 图片会被服务端视觉识别处理。必须先核查内部服务配置及代理/服务日志，避免对用户承诺超出实际控制范围的“不留存”。
3. 若视觉识别返回低置信度，前端不得用 AI 文案补全缺失特征。
